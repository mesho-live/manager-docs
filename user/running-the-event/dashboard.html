On this page

The event dashboard ​

Audience: Timing operators watching and running the event on the day.

The dashboard is your home base while an event runs — open it on the operator's screen and leave it up. It's the landing page for an event and gives you, at a glance, the event's status, how many competitors are still out, the health of your radio network, and one-click access to the jobs you do most. This page explains every card and indicator, and what to do when one changes colour.

The app bar: the event's state and what to do next ​

The bar across the top of every event page (not only the dashboard) names the event in bold, with its date and its facts beside it: individual, relay or team, the competition level, the discipline, an individual or mass start, and Eventor if it was imported from there. On the right are the Ask button (the built-in assistant), the event clock while the event is live, and the state button.

The state button says what the event is doing, in the colour of that state:

StateWhat it means
SetupNot started yet: you're still preparing it
LiveRunning
TestingRunning in test mode, because the event's date isn't today (see below)
Replaying / Replay completeA captured event being played back, for practice
Stopping…On its way to finished
InterruptedIt was live when Manager was closed or the computer stopped, and hasn't been resumed
AbandonedAn interrupted event you chose not to resume
CompleteFinished

Click the state button for its menu. The menu explains the state where the name alone doesn't, offers the one thing to do next as a large button, and always ends with Events (Back to events list), which closes the event page without stopping anything.

StateThe large buttonAlso in the menu
SetupStart eventReplay, when the event has captured data; Events
Live / TestingFinish event (Finish test in test mode)Events
ReplayingStop replay (Exit replay once it reaches the end)Events
Interrupted / AbandonedResume eventMark finished (Stop being asked to resume it), Replay, Events
CompletenoneRestart event (Make event live again), Replay, Events

When you open an event that is still being set up, its menu opens by itself for a few seconds, so Start event is in front of you.

Replay is a testing and training tool, not something you use on the day. It's offered only when the event has captured data to replay and no event is live.

The event menu ​

The menu down the left of every event page has Dashboard at the top, a switch between three modes — Course (courses, controls, legs, the map — radio placement opens from the map's page), Entries (competitors, classes, clubs, relay teams, starts, hire items) and Race (card downloads, radio punches, radios, live view, tracking, results, leaderboard, and under Admin: SportIdent station, screens, spectators, audit trail) — and a Go to… search at the foot (Ctrl+K, ⌘K on a Mac) that reaches every screen, every section of the event's settings, the dashboard's Add competitor, Import, On course, Not started and Pending, the event's Start, Resume, Finish and Mark finished (whichever its state offers), and the assistant, from any page. With the menu folded, the search opens in the middle of the page instead. A setup event opens on Entries; a live or finished one on Race. The ≡ button folds the menu to a column of icons. Every screen can be opened before the start; the race screens say what will fill them once the event starts. See Finding your way around an event for the full tour.

The Alerts panel ​

The narrow strip on the right of every event page is the Alerts panel. It opens by itself when something needs you — a radio's battery critically low, a lost connection — and keeps a log of everything else under Messages. See The alerts panel.

Starting and finishing ​

Start event (in the state menu) first runs Manager's pre-start checks. If they find anything — no courses, classes or competitors, classes with no course, or starts that go into the forest together — they're listed under Event validation warnings, and you can Continue anyway or Cancel and fix them.

Another event already being live doesn't stop it: both run (see Two events live at once). The one thing that does is a replay, which has to be stopped first.

An event dated in the future asks Start event in test mode? before it starts. A test-mode event runs exactly like a live one — downloads, radio punches, screens — so you can rehearse the day; the state button reads Testing and the menu's button Finish test.

Finish event asks you to confirm — finishing stops card downloads and radio punches for this event.

If anybody still has no settled result — no status, still on course, or a radio finish whose card hasn't been read — Event not finalised appears instead, listing them with the buttons that settle them. See Settling everyone first, and for everything else to do before you finish, the end-of-event checklist.

If Manager is closed while an event is live, the events list offers to resume it next time Manager starts. Decline, and the event is marked Abandoned; you can still Resume event or Mark finished from its state menu later.

Restarting an event you've already finished ​

Finishing an event isn't final. If a competitor walks out of the forest after you've closed the event off, open the event, click the Complete state button and choose Restart event. Manager warns you first, then takes the event live again so you can download the card, fix the result, and finish it a second time.

This works however long ago the event was — you can restart yesterday's event tomorrow morning. Reading a card late doesn't distort anything: the card holds the times of day the competitor actually punched, so their result comes out the same as it would have on the day.

Two things to know:

  • Another event can be live at the same time — see Two events live at once below. The one exception is a replay, which runs on its own.
  • Remember to click Finish event again when you're done, so the event goes back to being finished.

Note: An event that never ran and whose date has passed is the one case Manager won't start — its state menu offers no Start event, and says This event's date has passed, so it can't be started. Change the date first (Event details on the dashboard), then start it.

Two events live at once ​

Two events can be in progress on one Manager at the same time: a morning race whose last runners are still out when the afternoon race starts, or an MTBO and a foot-O on the same day. Start the second event as usual; the first carries on.

For the setup — how Manager tells the two events' runners apart, and what to check before the first start — see Running two events at once.

  • The radio network is shared. meshO Prime feeds every live event that uses it. A punch is stored in both events, and counts only in the event whose run it is: the one where its card is entered, or, for a card entered in both or neither, the one its start or check punch belongs to.
  • Each download desk reads into the event it has open. If the card belongs to the other live event, the result says so — This card is entered in Afternoon race (Jane Smith) — with a link to that event's download page. Read the card again there.
  • The radio card download station (cards read over the radio at the finish) sends each card to the live event where it is entered. If both events have it, the event where that runner has not downloaded yet wins, and after that the most recently started event. A card entered in neither goes to the event that adds competitors for unknown cards, if only one does, and otherwise to the most recently started event.
  • Finishing one event leaves the other running: its backups, its live results export, its liveresultat publishing and its radio feed all carry on.
  • Screens follow the most recently started event unless they are set to one: when the afternoon race starts, the leaderboards and other screens not set to an event move to it. The spectator site, the kiosk and the info displays ask which event to show.

A replay can't run while any event is live, and no event can start while a replay runs. A live standby follows every live event, and a take-over takes them all — see Live standby.

Event details and Edit dashboard ​

Above the tiles sit two buttons. Event details, on the left, opens the event's settings: its name and date, starts, radio controls, live results, cloud sync, quarantine, printing, hire items, the low-key options, extensions and backups. See Editing event details. (The Go to… search in the event menu opens any of those sections directly.) Edit dashboard, on the right, lets you rearrange the tiles — see Arranging the dashboard.

If this computer has just taken the event over from another one, a panel under them lists what is still to do by hand.

Always-on tiles ​

Three tiles are always available.

Event data ​

A count of everything you've set up — controls, courses, classes, competitors, teams and clubs. It's your at-a-glance check that setup is complete: a zero where you expect a number means something hasn't been imported or created yet. Click any count to jump straight to that list, and use Import (top-right) to bring in more data. See Importing event data.

Competitors ​

The headline numbers for the race in progress:

  • Total — everyone entered.
  • Not started — everyone who hasn't started. Before the first start that's the whole field; by the end of the day it's the no-shows, plus anyone already marked DNS, Not competing or Cancelled. Started and Not started always add up to Total, so marking a no-show DNS moves nobody between them.
  • Started — how many have started.
  • On course — how many Manager believes are still out on the course, including anyone who has checked in and not come back. This is your safety number.
  • Pending — runners who have crossed a radio finish but whose card hasn't been downloaded yet, so their result is still preliminary. (Only shown once radio punches are arriving.)
  • Finished — competitors who are back with a status: OK, MP, DNF, DSQ, overtime or not competing. Pending runners are counted here too, since the radio saw them finish; Pending tells you how many of those still need their card read.

A live mini-chart below the numbers tracks the On course count over time, so you can see the field flow out and back.

Not started, On course and Pending are clickable — they're drawn as coloured, raised buttons whenever they have something to show. Clicking opens the list behind each. At zero they look like the plain counts either side of them, so a coloured button always means there's a list to open.

The counts stay on one line whatever width you drag the tile to — they shrink, and their labels drop, rather than wrapping. Not started is the one that gives way: it isn't shown once the tile is too narrow to fit its label in full, since it's the only number you can work out from the others (Total minus Started). Widen the tile to bring it back. (It's measured against the label as your language actually writes it, so the width it needs differs between languages.)

Click Not started for the list of everyone yet to go out: name, card, class, start time and status. The Status column is what separates the two kinds of name on it — a blank status is somebody nobody has accounted for yet, while DNS, Not competing or Cancelled is an absence you (or a course closure) have already dealt with. Click a name to open their record, and click a column heading to sort by it. The dialog is described in full in The Not started dialog.

Safety — is everyone back? On course is the number that matters at the end of the day. While it's above zero, click it to open the On course list and work through who's still out, who has finished but not downloaded, and who never started. The full procedure — including reading start/finish station memory and clearing no-shows — is on its own page: Safety check: accounting for everyone. Click Pending to see the preliminary-result runners due at the download desk. For every other place the same picture surfaces, see Seeing who is still on course.

The other tiles ​

The rest of the dashboard depends on which features the event uses. A tile that only does something while the event is running — a card download, a radio punch — stays on the dashboard in setup and after the finish, but goes quiet and says so, rather than disappearing.

A few of these have their own pages:

  • Quick competitor actions is the fastest way to fix a single competitor's card or class without leaving the dashboard — for deeper edits, open them in the Competitors list. The printer button beside the search prints the selected competitor's splits, once their card has been read — see Printing splits. When you are done with one runner, click the × in the search to clear them and type the next name. Press Ctrl+F (⌘F on a Mac) anywhere on the dashboard to put the cursor in the search, ready to type a name; the empty search shows the key as a reminder. On any other page of the event the same key opens a search in the middle of the page: type part of a name, a bib or a card number and press Enter to open that competitor. The eye button beside the search opens the competitor's full record. Type a new card number or pick a new class and press Set beside it; the tile shows their Course, Status and, while they're out, where they were Last seen. With a SportIdent reader connected, click into the Card number box and insert a card to fill in its number, rather than downloading it. At an event where allocated start times win, an Allow punching start button also appears for a runner left on the event's setting, so a runner who was late to the start through no fault of their own is timed from their start punch — see Punched starts.

  • Download card is a compact version of the full Card downloads page. A reader connected here is the same reader the Card downloads page and the SportIdent station page use, and downloads register from anywhere, so the tile updates even when you're elsewhere. When cards are waiting for an owner, the tile says how many, with Show to list them.

  • Radio controls is your radio-network health panel. While meshO Prime isn't connected it shows Prime's state — Searching, Lost, Offline or Not configured — with a Diagnostics button. Once Prime is Online it shows a bar chart of punches over the last 30 minutes, a coloured dot per meshO Control (green when heard in the last two minutes, orange after two, red after five, grey if never heard), a count of low batteries, and the alerts for each unit: battery low or critical, connection lost, weak signal, no location. Click the alerts chip to list the units that have one, with View all radios at the foot. The arrow at the top right opens the Radios page.

See also Radio punches.

  • Spectators is a summary of the Spectators page (in the event menu's Race mode, under Admin) — see Spectator analytics.
  • Radio punch forwarding and SIRAP punch listening show the destination or port, whether they are working, and their counts — see Forwarding and receiving punches.

  • Liveresultat shows the competition ID, links to its Organiser page and Spectator page, whether it is Published, the publisher's Status (Idle, Sending, Not started), when it Last sent and Last checked, and an activity chart. It is covered in Publishing live results online.

  • Extension tiles come from add-ons you've installed — see Installing extensions and Using an extension in an event.

Recent downloads — a tile you switch on ​

Recent downloads starts off the dashboard, because the Card downloads page already lists every download in full. Add it when you want the last few in the corner of your eye: click Edit dashboard in the event header, choose Add tile → Recent downloads, drag and resize it where you want it, then click Done. It stays there for next time.

The tile shows one card per download, newest at the top: the time it was read, the competitor's name and their status chip. Click one to open that competitor's record, which is where you change a class or fix a mis-punch — the same dialog you get from the Competitors list.

It shows exactly as many as fit in the tile and no more — it never scrolls, and never cuts a name in half. Make the tile taller to see further back. Narrow it and the time drops off, so names keep their room; widen it and the time comes back.

A card that hasn't been matched to anybody yet shows its card number and an Unassigned chip instead. Click that one and you land on the Card downloads page with the card already open, ready to give it an owner — every card in the tile goes somewhere.

Like the Download card tile, it stays on the dashboard but goes quiet when the event isn't running — cards can only arrive while the event is live.

Pending downloads — the tile the download tent watches ​

Pending downloads is the mirror image: not the cards that have come in, but the ones that haven't. It lists the runners a radio finish saw come back whose card has never been read — the people who walk off towards the car park with it still in their hand.

It starts off the dashboard too, because the Pending downloads info screen is where the tent usually watches this list. Add it the same way: Edit dashboard → Add tile → Pending downloads.

Longest wait at the top. Each row carries the time the radio put them across the line, their name, and how long they have been waiting since — counting up once a second, from the event clock. Click a row to open that competitor's record, which is where somebody who never came back is marked DNF, or the wrong card number that is why nothing was ever read against them gets fixed.

Runners still on course are deliberately not on it, exactly as on the info screen: they are a different problem — somebody who may still be running — and on the same list they would bury the two or three names the tent is actually chasing.

--:-- means Manager cannot say, not zero. A runner whose finish time it never recorded, or an event with no clock running, shows the sentinel rather than a number. Their name is still on the list; that is the part that matters.

Like Recent downloads, it sizes itself to the tile — as many whole rows as fit, never scrolling and never half a name — and it stays on the dashboard but goes quiet when the event isn't running.

Arranging the dashboard ​

Click Edit dashboard in the event header to rearrange the tiles. While editing you can:

  • drag a tile to move it, and drag its edges to make it wider, narrower, taller or shorter;
  • Hide a tile you don't use;
  • Add tile to bring back a hidden one, or add one that starts hidden, such as Recent downloads or Pending downloads;
  • Reset layout to go back to the default arrangement.

Click Done when you're finished. The arrangement is kept in this browser, and it's the same for every event you open on this computer; another computer has its own.

Reading the colours ​

Colour is used consistently across the dashboard so problems catch your eye:

  • Purple — an event in Setup.
  • Green — healthy or live: a live event, a connected reader (Listening), forwarding that's Active, controls reporting in normally.
  • Orange / yellow — attention, not yet a failure: punches Queued for forwarding, a control on low battery (25% or less), weak signal or quiet for two minutes, an interrupted event.
  • Red / grey — stopped or finished: an abandoned (red) or complete (grey) event, a critical battery (5% or less), a control not heard for five minutes, or (grey) never heard at all.

When the Radio controls tile flags low batteries or a silent control, treat it as an early warning and check that unit before it costs you punches.

What isn't on the dashboard ​

A couple of common jobs live elsewhere, by design:

  • Marking competitors DNS in bulk is done from Competitors → Actions → Set competitors DNS…, not here. See Safety check.
  • Re-checking a download, overriding a status, or editing punches is done from the Card downloads page or the competitor's record — see Resolving issues on the day.
