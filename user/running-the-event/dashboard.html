The event dashboard ​

Audience: Timing operators watching and running the event on the day.

The dashboard is your home base while an event runs — open it on the operator's screen and leave it up. It's the landing page for an event and gives you, at a glance, the event's status, how many competitors are still out, the health of your radio network, and one-click access to the jobs you do most. This page explains every card and indicator, and what to do when one changes colour.

The top bar: status and event controls ​

The strip across the top of every event page (not just the dashboard) carries the event's lifecycle:

  • Status chip — the event's current state, also echoed as a coloured stripe down the left of the header card below:
    • Setup mode — not started yet (you're still preparing it)
    • Event in progress — live; the chip pulses
    • Event stopping / Event interrupted — paused or interrupted mid-run
    • Event completed — finished
    • Event abandoned — ended without completing
  • Event clock — a running event time, shown while the event is in progress.
  • The primary button changes with the state: Start event (in setup), Finish event (while live), or Resume event (for an interrupted or abandoned event, alongside Mark finished). Once an event is finished there's nothing left to do, so Close becomes the primary button and Restart event sits alongside it as a quiet, secondary option.
  • Replay controls appear when an event has captured data to replay; this is a testing/training tool rather than something you use live.

Restarting an event you've already finished ​

Finishing an event isn't final. If a competitor walks out of the forest after you've closed the event off, open the event and click Restart event in the app bar. Manager warns you first, then takes the event live again so you can download the card, fix the result, and finish it a second time.

This works however long ago the event was — you can restart yesterday's event tomorrow morning. Reading a card late doesn't distort anything: the card holds the times of day the competitor actually punched, so their result comes out the same as it would have on the day.

Two things to know:

  • Only one event can be live at a time. If another event is running, finish it first.
  • Remember to click Finish event again when you're done, so the event goes back to being finished.

Note: An event that never ran and whose date has passed is the one case Manager won't start — there's no Start event button for it. Change the date first (Edit event details), then start it.

The event header ​

The card at the top of the dashboard identifies the event: its name, date, and a row of attributes — event type (individual / relay / team), competition level, discipline, and whether it's an individual or mass start — plus an Eventor marker if it was imported from Eventor. The left border is colour-coded to the status.

The cog button (top-right of the card) opens Edit event details, where you change the name, date, radio-control settings, mass start, splits printing, hire items, and extensions. See Editing event details.

Always-on cards ​

Three cards are always present.

Event Data ​

A count of everything you've set up — controls, courses, classes, competitors (or teams for a relay), and clubs. It's your at-a-glance check that setup is complete: a zero where you expect a number means something hasn't been imported or created yet. Click any count to jump straight to that list, and use Import (top-right) to bring in more data. See Importing event data.

Competitors ​

The headline numbers for the race in progress:

  • Total — everyone entered.
  • Not Started — everyone who hasn't started. Before the first start that's the whole field; by the end of the day it's the no-shows, plus anyone already marked DNS, Not competing or Cancelled. Started and Not Started always add up to Total, so marking a no-show DNS moves nobody between them.
  • Started — how many have started.
  • On Course — how many Manager believes are still out on the course. This is your safety number.
  • Pending — runners who have crossed a radio finish but whose card hasn't been downloaded yet, so their result is still preliminary. They sit between On Course and Finished. (Only shown once radio punches are arriving.)
  • Finished — competitors with a downloaded card and an authoritative result.

A live mini-chart below the numbers tracks the On Course count over time, so you can see the field flow out and back.

Not Started, On Course and Pending are clickable — they're drawn as coloured, raised buttons whenever they have something to show. Clicking opens the list behind each. At zero they look like the plain counts either side of them, so a coloured button always means there's a list to open.

The counts stay on one line whatever width you drag the tile to — they shrink, and their labels drop, rather than wrapping. Not Started is the one that gives way: it isn't shown once the tile is too narrow to fit its label in full, since it's the only number you can work out from the others (Total minus Started). Widen the tile to bring it back. (It's measured against the label as your language actually writes it, so the width it needs differs between languages.)

Click Not Started for the list of everyone yet to go out: name, card, class, start time and status. The Status column is what separates the two kinds of name on it — a blank status is somebody nobody has accounted for yet, while DNS, Not competing or Cancelled is an absence you (or a course closure) have already dealt with. Click a name to open their record.

Safety — is everyone back? On Course is the number that matters at the end of the day. While it's above zero, click it to open the On Course list and work through who's still out, who has finished but not downloaded, and who never started. The full procedure — including reading start/finish station memory and clearing no-shows — is on its own page: Safety check: accounting for everyone. Click Pending to see the preliminary-result runners due at the download desk. For every other place the same picture surfaces, see Seeing who is still on course.

A few of these have their own pages:

  • Quick Competitor Actions is the fastest way to fix a single competitor's card or class without leaving the dashboard — for deeper edits, open them in the Competitors list. The printer button beside the search prints the selected competitor's splits, once their card has been read — see Printing splits. When you are done with one runner, click the × in the search to clear them and type the next name. At an event where allocated start times win, an Allow punching start button also appears for a runner left on the event's setting, so a runner who was late to the start through no fault of their own is timed from their start punch — see Punched starts.
  • Download Card is a compact version of the full Downloading cards station — and, as that page explains, downloads register from anywhere, so the tile updates even when you're elsewhere.
  • Radio Controls is your radio-network health panel. Low battery or a control that's gone quiet shows here first; for setup and recovery see Connecting meshO Prime and radios and Radio punches.
  • Extension tiles come from add-ons you've installed — see Installing extensions.

Recent downloads — a tile you switch on ​

Recent downloads starts off the dashboard, because the Downloading cards page already lists every download in full. Add it when you want the last few in the corner of your eye: click Edit dashboard in the event header, choose Add tile → Recent downloads, drag and resize it where you want it, then click Done. It stays there for next time.

The tile shows one card per download, newest at the top: the time it was read, the competitor's name and their status chip. Click one to open that competitor's record, which is where you change a class or fix a mis-punch — the same dialog you get from the Competitors list.

It shows exactly as many as fit in the tile and no more — it never scrolls, and never cuts a name in half. Make the tile taller to see further back. Narrow it and the time drops off, so names keep their room; widen it and the time comes back.

A card that hasn't been matched to anybody yet shows its card number and an Unassigned chip instead. Click that one and you land on the Downloading cards page with the card already open, ready to give it an owner — every card in the tile goes somewhere.

Like the Download Card tile, it stays on the dashboard but goes quiet when the event isn't running — cards can only arrive while the event is live.

Pending downloads — the tile the download tent watches ​

Pending downloads is the mirror image: not the cards that have come in, but the ones that haven't. It lists the runners a radio finish saw come back whose card has never been read — the people who walk off towards the car park with it still in their hand.

It starts off the dashboard too, because the Pending downloads info screen is where the tent usually watches this list. Add it the same way: Edit dashboard → Add tile → Pending downloads.

Longest wait at the top. Each row carries the time the radio put them across the line, their name, and how long they have been waiting since — counting up once a second, from the event clock. Click a row to open that competitor's record, which is where somebody who never came back is marked DNF, or the wrong card number that is why nothing was ever read against them gets fixed.

Runners still on course are deliberately not on it, exactly as on the info screen: they are a different problem — somebody who may still be running — and on the same list they would bury the two or three names the tent is actually chasing.

--:-- means Manager cannot say, not zero. A runner whose finish time it never recorded, or an event with no clock running, shows the sentinel rather than a number. Their name is still on the list; that is the part that matters.

Like Recent downloads, it sizes itself to the tile — as many whole rows as fit, never scrolling and never half a name — and it stays on the dashboard but goes quiet when the event isn't running.

Reading the colours ​

Colour is used consistently across the dashboard so problems catch your eye:

  • Green — healthy or live: an in-progress event, a connected reader (Listening), forwarding that's Active, controls reporting in normally.
  • Orange / yellow — attention, not yet a failure: punches Queued for forwarding, a control on low battery or weak signal, an interrupted event.
  • Red / grey — stopped or finished: an abandoned (red) or completed (grey) event, a critical battery, a control that hasn't been heard from.

When the Radio Controls card flags low batteries or a silent control, treat it as an early warning and check that unit before it costs you punches.

What isn't on the dashboard ​

A couple of common jobs live elsewhere, by design:

  • Marking competitors DNS in bulk is done from the competitor lists (the dedicated Set DNS dialog), not here. See Safety check.
  • Re-checking a download, overriding a status, or editing punches is done from the Downloading cards page or the competitor's record — see Resolving issues on the day.
