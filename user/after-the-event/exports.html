How a competitor is identified in an exported file ​

Every results, start-list and entry-list export — IOF XML, OJSON and Upload to Eventor alike — names each competitor by the identifiers they hold: their Eventor ID (your own competitor number) and their IOF ID. In IOF XML the competitor number comes first and the IOF ID follows it marked as the IOF's, so a system that reads only the first one still finds the number it always did. A competitor holding neither is exported by name alone. The CSV entry and start lists carry both as the Database Id and IOF Id columns, and all of them read both back when imported into Manager.

To fill in IOF IDs for a field that arrived without them, see Importing IOF IDs.

Exporting one country's results ​

Publish → Export IOF XML and Publish → Export JSON open a dialog that, alongside the classes, asks which Countries to include. Everything starts selected, so the file carries every country unless you untick some — handy when a national federation wants only its own runners.

  • A competitor's country is their club's. A relay team goes by the team's own club, so a team is always exported whole.
  • No country covers competitors whose club has no country recorded (or has a dash, -, where the code would be), and competitors with no club at all.
  • Places are not renumbered. A runner who came fourth in the class is fourth in the file, whoever else was left out.
  • The list only appears when there is more than one choice — a single country plus No country counts. The PDF, Print and Upload to Eventor actions don't offer it: Eventor must get every runner in each class you upload, or it reads the rest as never having entered.

Each country shows with the code its clubs were given. If some clubs were given the IOC code (SUI) and others the ISO code (CHE), both appear — tick both.

Combining classes for the World Ranking (IOF XML) ​

The IOF asks a World Ranking event for a results file in which every class that ran a course is merged into one list and ordered — the ranking points are worked out over everyone on the course, not class by class. At a Middle where M21E and M20E run one course, and W21E and W20E another, that is two merged lists; at a sprint where M18A runs with them, three classes in each.

Publish → Export IOF XML has an IOF XML options line for this: click Change beside it. In the dialog that opens, either click Combine by course — each set of the classes in the export that ran the same course becomes one combined class — or click Add combined class and pick its classes yourself. Click Done, check the line in Publish options now lists your combined classes, and export as usual. Nothing is remembered: the next export starts again with nothing combined.

  • Each combined class is published once, with everyone in it ordered by time. Places and time behind are worked out across the combined list, so an M20E runner who beat half of M21E is placed among them.
  • Each combined class has a Class name, Class id and Course name. Left blank, the file uses its own: the class is named after its classes (M21E + M20E) with their ids joined (1+2), and the course after the class. Fill them in when the World Ranking event was set up with names of its own — Men, ME and so on. Two classes in one file can't have the same id; the dialog says so beside the field.
  • Nothing in the event changes. The classes stay separate everywhere else — on screen, in the JSON export, in the PDF and on Eventor. Export the ordinary file as well if anyone needs the classes apart.
  • Combine by course counts classes as running the same course when they were given the same courses on the Classes page; a class alone on its course is left as it is. Only individual classes can be combined — never relay classes — and a class can be in one combined class only.
  • Classes you leave ticked but that aren't combined are exported as normal alongside — untick them from Classes if the IOF wants the World Ranking classes only. Untick a class you combined and it simply drops out of its combined class.

Leaving out organisation ids ​

The same dialog has Leave out organisation ids. Each competitor's club is still named in the file, with its country; only meshO's own number for the club is left out. That number means nothing to a system that numbers clubs its own way, such as the IOF World Ranking, which may otherwise try to match on it. A relay team's club keeps its id.

Exporting the entry list ​

Who has entered — as opposed to when they start or how they got on — is exported from the Competitors page: Actions → Export entry list, in IOF XML, OJSON or CSV. It's written up where the menu lives: see Exporting the entry list.

Two things worth knowing before you reach for it:

  • The export is always the whole event, never the filtered list you're looking at.
  • The CSV is designed to be edited and re-imported — though not every column comes back. The round-trip table says which do.

Exporting a multi-stage event ​

Both standings exports live on the Actions menu of the carnival's Standings tab, alongside Recompute.

Overall standings as CSV — Export CSV. One row per competitor, one column per stage, plus the total: the shape a prize-giving spreadsheet wants. A stage that didn't count is bracketed rather than blanked, and a provisional total keeps its *, so the file says what the screen said. Export one class or all of them.

Overall standings as PDF — Export PDF. The table laid out for printing or pinning up, matching whatever you have on screen: the class or combined view you have selected, and your Show and Times settings.

IOF XML per stage — export a stage's results as IOF XML the usual way. Because the event is a stage, the file also carries the stage's raceNumber and each competitor's overall standing after that stage as an IOF OverallResult. Every stage up to it has to be settled first — a runner left with no status on an earlier day holds the file up, and the export tells you who (see What an exported results file contains). That is the IOF standard's own answer to multi-stage results, so SplitsBrowser, Eventor and Livelox read it with no bespoke format. A standalone event's export is unchanged.

See Multi-stage events.

A knock-out competition's classification has no export yet — it is on screen only. Each round's own results export normally, as any event's do. See Knock-out competitions.

Exporting as OJSON ​

Everything Manager exports as IOF XML it also exports as OJSON — a published format with a JSON Schema, carrying the things the XML has no room for: split-time columns as data, a relay team's own result, whether a split came from a card or a radio, and millisecond precision. If you are writing something that reads a Manager event — a club results page, a spreadsheet pipeline, an app — that is the format to read.

See OJSON for the endpoints, the field reference and the schema.
