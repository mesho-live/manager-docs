Settings ​

Audience: Event organisers and operators setting up Manager on a computer.

What each page of Settings controls. Settings belong to the computer running Manager and apply to every event on it; many are only defaults that each event can change for itself in Event details.

Opening Settings ​

Click the cog at the top of the Events list. The pages are listed down the left, in five groups: Global registry, Printing, Integrations and devices, System and Appearance.

Most pages show Unsaved changes with Save and Discard at the bottom once you change something; nothing applies until you save. The registries, the Printers page and This computer save as you go instead. A few settings, such as AI assistants and HTTPS, also need the server restarting, and say so.

Settings aren't part of an event. They stay on this computer, so a backup or an event moved to another computer doesn't take them along. See Moving an event to another computer.

Global registry ​

Lists that every event on this computer shares.

Club registry and Competitor registry ​

The clubs and people Manager knows, used to suggest names, clubs and card numbers as you type and at the registration desk. They can be refreshed from Eventor. See Club Registry and Competitor Registry.

Hire card registry and Other hire registry ​

The pool of hire-card numbers your club lends out, each with an optional Owner, and the other things you lend: compasses, map boards. See Hire items.

Custom fields ​

Extra fields recorded against every competitor, beyond the built-in ones. Shared across all events, so the same set is there for every event you run.

  • Each field has a name of your choosing and holds either text or a number. The type decides how the value sorts in a column: a Number field sorts numerically, so 9 comes before 10 rather than after it. Values are always stored as text either way, and a value that can't be read as a number sorts last.
  • Use Move up / Move down to set the order fields appear in, everywhere they are shown.
  • Renaming a field keeps the values competitors already hold. Removing one hides it without deleting those values, so adding the field back under the same name brings them with it — under different wording it is a new, empty field.
  • Fields appear on the Custom fields tab of a competitor, on a Competitor registry entry, and as optional columns in the Competitors list and the Competitor registry table. In the Competitors list they are off by default (turn them on from the Columns menu); in the registry table they are shown by default.
  • Values recorded on a Competitor registry entry follow that person into every event they enter: they are copied onto the competitor when you import entries from Eventor or from an IOF XML entry list, and when you pick the person from the registry in the Edit Competitor dialog. A value already on the competitor always wins, so re-importing an entry list never overwrites a correction you made in the event — it only fills in fields that are still blank.
  • For an IOF XML file, the link relies on the file carrying the athlete's IOF ID. Entry lists exported by Eventor normally do; a file without it cannot be tied to a registry person, so those competitors arrive with the fields blank. Card number and name are deliberately not used for the match, because hire cards change hands.
  • Custom fields are not included in exports — not in IOF XML, results, or splits printouts. They are for your own records.
  • If you have enabled AI assistants (MCP), custom fields are among the competitor details an assistant can read. Bear that in mind for anything sensitive, such as a phone number.

Printing ​

Every printer, and what is printed on it. The full guide is Printing splits.

  • Printers — every printer Manager can print on, and every computer it is open on, drawn as a live map and then listed: printers on the network, printers plugged into the server's computer (through Windows, or the print system of a Mac or Linux computer), and USB printers plugged into a laptop running Manager. Each printer has a name (where it stands — Lane A, Results board), its own paper width, and either its characters per line and paper cut (a thermal printer) or its text size, boldness and line spacing (a printer drawn for its driver). Add a printer starts by asking where it is plugged in. A laptop's USB printer is shared with every computer to begin with, while Manager is open on that laptop. This computer shows the printer plugged into the computer you are at and where its splits and labels print; Set up here before? lets a laptop opened at a new web address pick up the setup it had. Nothing on this page waits for the Settings Save button: a printer is saved from its own dialog, and a computer's choices apply as you make them.
  • Splits print — the Default splits printer (or Not printed; it must be a printer every computer may use), where each computer's splits print, and then when a slip prints and what is on it: auto-print on download, whether a mis-punch printout is held while you correct the class and for how long, logo, top 3 places, the mistakes and strong legs sections, splits language, and the QR code. Each event can override when and what in Event details → Printing.
  • Result labels — a small printout per competitor for the results board, independent of the splits, and laid out as the splits print is. Where: the label printer (Not printed, the splits printer straight after the splits, or a printer of its own; like the default splits printer, one every computer may use) and where each computer's labels print. When: its own switch (off to begin with) and its own mis-punch hold. Layout: a three-row layout with a preview and a test print.
  • Upgrading from a version before printers and computers: see What an upgrade does to printing.
  • Radio downloads — whether a card read by a radio download station and sent over the meshO network prints its splits and label, and where, since no computer read it. Each event can override these.

Integrations and devices ​

Eventor ​

Connects Manager to Eventor, to create events from it, import entries and start times, refresh the registries, and upload start lists and results.

  • Enable Eventor, then your Host name, API key and Organisation ID (your organisation's number in Eventor, which scopes the events shown and the competitors and clubs fetched).
  • Event history — how far back the import picker lists events. Future only is quickest; each extra month of history is another request to Eventor.
  • Events list — offer upcoming Eventor events beside your own on the Events list, filtered by Organisations and Event name contains, so you can create an event from one with a click.

See Creating an event from Eventor.

Cloud sync ​

Publishes events to the meshO cloud (events.mesho.live), where spectators can browse their results online. It is set up out of the box: the Cloud URL points at the meshO cloud, and the Push token field is left blank because Manager carries its own token for that server.

  • Publish events to the cloud automatically when they are finished is on to begin with. When you finish an event (or use Mark finished), it is queued and uploaded in the background — you do not wait for it, and nothing about finishing changes.
  • No internet at the venue is fine. The queue is kept with the event on disk, so you can finish, close the laptop and drive home: the event goes up the next time this computer is online, including after a restart. While an event is live nothing is uploaded, so the upload never competes with radio punches or live results for the venue's connection.
  • Each event card shows where it stands with a small grey cloud beside the status chip: a tick once it is on the cloud (hover for when), a clock while it is waiting. A cloud with an exclamation mark, in the warning colour, means something waiting will not fix — a refused token, or an event larger than the cloud accepts — and hovering says which.
  • Turning automatic sync off stops new events being queued and also pauses any that are already waiting, so it is the way to stop an upload that has not happened yet. You can still publish any event by hand with its Push to cloud action.
  • Running your own cloud server? Put its address in Cloud URL and its token in Push token. Manager's own token is only ever sent to the meshO cloud, never to another server. Clearing the Cloud URL turns cloud sync off altogether.
  • What gets published is the whole event — competitors' names, clubs and results — on a public site. If an event should not be public (a training run, a private club event), turn its automatic sync off before you finish it: each event can decide for itself in Event details → Cloud sync, whatever this setting says.
  • Event details → Cloud sync also lists every time the event has been synced (when, whether it was published, updated or deleted, whether that was automatic or by hand, and how much was uploaded), links to its page on the cloud, and has Delete from the cloud, which takes it off the public site. The event on your computer is not touched, and its automatic sync is switched off, so finishing it again does not put it back.

Live standby ​

Lets a second meshO Manager on the network keep a live copy of the running event, ready to take over if this computer fails: the switch that allows it, this computer's address and pairing code to type on the standby, what else the standby copies (settings and PIN, the HTTPS certificate, printers and computers, the registries), and which standbys are following now. See Live standby.

Radio punches ​

meshO Prime and the radio-punch connections, on one page:

  • meshO Prime — Use meshO Prime for radio punches: the default for new events. Each event can change it on Event details → Radio Controls. See Connecting meshO Prime and radios.
  • Radio punch forwarding — sends radio punches on to other timing software over TCP: TCP host, TCP port, Protocol (SIRAP or OE12) and Client name, with Test connection.
  • Radio punch listening — accepts SIRAP punches from another system on a Listen port.

See Forwarding and receiving punches.

Video ​

what this server does with the pictures a camera sends it (cameras themselves are set up on the device holding them, at /info → Camera — see Info screens). Record cameras by default decides whether a camera records as well as showing a live picture, unless whoever sets it up turns that off for theirs; Keep recordings for (days) is how long one is held before Manager tidies it away, with 0 meaning until you delete it yourself; Minutes per recording file is how much each file covers; Picture quality (kbit/s) is what a camera is asked to encode at, with the resulting MB per hour shown beside it; Stop recording below (MB free) is the disk floor recording gives way at, so a full disk cannot take the event down with it; Ride out a dropped connection for (seconds) is how long a camera holds pictures it cannot send and how long its recording waits for it. The panel also shows what this event's video is costing, how much room is left, and where on disk it is — recordings are kept outside the event folder, so they are in no event backup and no cloud sync.

System ​

Event defaults ​

Values for events. Most are copied into a new event when it's created, so changing them later doesn't change events you already have; each event changes its own in Event details.

  • Start, Finish and Check codes — the codes your start, finish and check units punch as. See Start, Finish and Check codes.
  • Event type, Competition level, Discipline and Course format for a new event.
  • Punching starts override allocated starts — whether a start-unit punch replaces an allocated start time.
  • Time runners with no start from check punch or midnight — on to begin with. Unlike the others, this one isn't copied: every event follows it unless it has chosen otherwise on its Starts tab, so changing it re-scores any running event that follows it. See A runner with no start time.
  • Timing card system — SportIdent or EMIT, for a new event.
  • Leaderboard screen defaults — how a new leaderboard screen starts: club display and logo, auto-scroll, header, how many radio controls per class, how times are shown, team members on one line, and how many places per class. Each screen changes its own. See Creating screens.
  • Default replay speed — for replaying a captured event, a testing and training tool.

Server ​

  • This computer's name and LAN IP, and how to rename the computer for a friendlier address.
  • HTTP port — 5154 to begin with.
  • Allow access from other devices on the network — on to begin with. Off, only this computer can open Manager.
  • Access links — the links to give every other device: Manager, Registration, Spectator, Kiosk, Info and Commentary, each by name and by IP, with Show QR code to open one on a phone. See Reaching the server: name or IP.
  • Enable HTTPS — for download and station-backup laptops, which need a secure link to use a card reader. See HTTPS and certificates.

Access protection ​

Sets a PIN that has to be entered before any manager screen, including the Events list, event editing and Settings, can be opened. The leaderboard, commentary and spectator screens stay public. Set one whenever the event's network is shared with people who shouldn't be editing it. A forgotten PIN can be cleared from the tray or menu bar: Reset Access Protection PIN.

Auto update ​

Automatically install updates downloads and installs new versions as they come out, and restarts the server. Check for updates checks now. Update notices are hidden while an event is live. See Updating.

AI assistants ​

Lets an AI assistant read the live event over MCP, and optionally make changes. Off to begin with; both switches need a server restart. See AI assistants (MCP).

Logging ​

Log level: how much detail Manager writes to its log file. Every event's audit trail is always recorded, whatever this says. Leave it alone unless support asks. See Where the logs are.

Auto backup ​

The defaults for automatic backups while an event is running: on or off (off to begin with), how often (5, 10, 15, 30 or 60 minutes), and how many to keep per event (1, 2, 5, 10 or All; 5 to begin with). Each new event starts with these, and changes its own on Event details → Backup & export. See Backup and restore.

Appearance ​

This computer ​

Settings for the browser you're using, saved on this computer only, plus two that apply to everyone:

  • Computer name — shown in the audit trail against every change made here. See Naming a computer.
  • Default language — the language every computer and screen starts in. Applies to everyone.
  • Language on this computer — overrides the default for this browser only.
  • Interface scale — how large Manager draws on this screen.
  • Theme — light, dark, or follow the device, for each kind of screen: Manager, Registration, Commentary, Leaderboard, Kiosk and Spectator. Applies to everyone.

Where settings are kept ​

Settings, the registries, and the printer and computer lists are stored in Manager's app-data folder on the server computer. The settings themselves are in meshO Manager.yaml:

ComputerFolder
Windows%LOCALAPPDATA%\meshO Manager
macOS~/Library/Application Support/meshO Manager
Linux~/.local/share/meshO Manager

Change settings in Settings rather than in the file. Manager checks what it is given there, and it can overwrite a hand-edited file while it's running. Events are kept separately; see Where backups are kept.

There's no button to put every setting back to how it started.
