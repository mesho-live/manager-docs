Controls and radio controls ​

Audience: Event organisers setting up timing points.

In Manager a control carries one or more control codes. A radio control is one whose punches also report back live during the event, so they surface on Spectator, Leaderboard and Commentary as runners pass through.

This page covers how Manager models controls, how radio controls work, the special Start / Finish / Check controls, and how to create, edit, and manage all of them. As with classes and courses, most events get their controls from an import — see Importing event data — so usually you're reviewing and marking radios rather than entering controls from scratch.

Two kinds of control ​

Manager models normal controls and the special controls — Start, Finish, and Check — differently:

  • Normal controls carry one or more control codes and are matched to a punch by code.
  • Start, Finish and Check controls carry no code of their own in Manager. They anchor courses by position for card downloads. Their radio punches are recognised by codes you list on the event itself — see Start, Finish and Check codes below.

Tip: A course doesn't have to use a Start or Finish unit at all. Set its Start to First control (or its Finish to Last control) and a normal, numbered control does the job — handy when the start unit was left behind, or one "meta" control is the start, every transition and the finish. See Starting or finishing at a numbered control.

The split matters because a Start, Finish or Check punch from a download carries no course code — only the fact that it happened. Radio punches from Start, Finish and Check only carry a code — so Manager has to map that code to the special meaning. Everything else is treated as a normal control along the course.

Note: Manager accepts normal control codes from 31 to 511 — 1–30 are reserved for SportIdent's special stations.

The Controls page ​

Switch the event menu to Course and choose Controls.

The table shows one row per control. The columns button at the right-hand end of the header row turns columns on and off, and headings can be dragged to reorder:

  • Control — the control name. Click it (or the pencil icon) to open the Edit control dialog.
  • Control codes — the code(s) this control uses. Start, Finish and Check controls show None configured here, since they carry no code. If a replacement code has been set, the original code appears struck through with the replacement beside it. A control marked faulty shows its code struck through with a Faulty chip.
  • Is radio — a toggle showing whether this control reports radio punches. Start, Finish and Check show Auto: Manager handles them itself (see Start, Finish and Check codes), so there is nothing to switch.
  • Radio name — an optional custom display name used on Leaderboard and Commentary.
  • Time offset — any clock correction applied to this control's punches, shown as +HH:MM:SS.
  • Clock — how far the control's station clock is out, judged from its radio punches. See Checking a control's clock.
  • Radio enabled — whether the station's own short-range (SRR) radio was set to send, as read off the SIAC cards that punched it. Hidden until you turn it on; see Radio enabled (SRR).
  • Points — what the control is worth on a score course. Shown once the event has a score course; see Points for score courses.
  • Courses — how many courses use this control. Click to see the list.

Filter the table with Search control (by name) or the Is radio filter. The question-mark button at the right-hand end of the page header opens a short explanation of the page and its columns; click it again to close it.

The Actions menu (top right) has:

  • Add control… — create a new control (see below).
  • Delete all controls… — see Deleting all controls.

Leg distances are edited on the Legs page; see Leg distances.

Creating a control by hand ​

Click Actions → Add control…. The Add control dialog opens.

Fields:

  • Type — required. Choose Start, Finish or Normal. (There's no Check option — every event is seeded with a single, permanent Check control. Several check units share it: list each unit's code under Check codes.)
  • Control Code — shown for Normal controls only, and required. Enter a number from 31 to 511. Manager rejects a code that's out of range or already used by another control.

Manager names the control automatically: a Normal control takes its code as its name, while Start / Finish controls auto-number — Start, then Start 2, Start 3, … as you add more. To give a Start or Finish a custom name, rename it afterwards on the Edit control dialog's Name tab.

Click Add.

Tip: You rarely need to add Normal controls here first — when you build a course on the Courses page you can type a control code straight into the course and Manager creates the control if it doesn't exist yet. Use Add control mainly to add an extra Start or Finish for a split-start or two-finish event.

Editing a control ​

Click a control's name (or its pencil icon) to open the Edit control dialog. Which tabs appear depends on the control's type:

Control typeTabs available
NormalRadio, Replacement, Time offset, Faulty — plus Points at an event with a score course
Start / FinishName, Time offset
CheckTime offset

The tabs run down the left of the dialog, under the control's name and its code. Save keeps your changes; Cancel discards them.

Two more tabs appear on any control when there is something to show: Clock, once meshO Control radios have reported punches from it (see Checking a control's clock), and Location, once the event has a map and the control has been placed on it — the event map around the control, with nearby controls faded.

Placing controls on the map is covered in Event map and radio placement.

Name (Start / Finish only) ​

Rename the control. Names must be unique within their type (no two Starts can share a name). A Start or Finish also has a Delete button at the bottom left of the dialog, which asks once more before it deletes. It is greyed out, with the reason beside it, when this is the last Start (or Finish) the event has; one that a course still uses is refused when you confirm (see Multiple Start, Finish and Check controls). Normal controls aren't renamed here — they're identified by their code. A radio control can carry a display name instead: see Radio name on the Radio tab.

Radio (Normal only) ​

This is where you make a control a radio control:

  • Is radio — toggle on to have this control's punches reported live. Radio controls are shown on Leaderboard and Commentary screens for classes that use them.
  • Radio name — an optional friendly display name (e.g. "Spectator control", "Last control"). Leave it blank to use the control's name. It can only be set while Is radio is on.

You can also flip Is radio directly from the toggle in the Is radio column on the Controls page, without opening the dialog.

Radio enabled (SRR) ​

Below a divider, the same tab shows Radio enabled: whether the control's SportIdent station had its own short-range (SRR, "AIR+") radio set to send, which is what lets a nearby radio pick up a copy of a SIAC punch. This is read off the cards that punched it — something Manager observes, never something you set here. Only a SIAC records the setting, so a control punched only by other cards shows Not observed, which is not the same as off. If the reading changed during the day (the unit was reconfigured), the tab says what it was before and lists the readings.

Tip: With Auto-mark controls as radio controls on (the default — see Auto-marking controls as radios below), you often don't need to set Is radio by hand at all: the first live punch from a control flips it on for you.

Replacement (Normal only) ​

  • Replacement code — Alternative code if this control was replaced during the event with a station using a different number. See Renumbered or swapped controls below.

Time Offset ​

  • A cumulative correction applied to every punch recorded against this control — card downloads and radio punches alike. Set a sign (+ or −) and enter Hours, Minutes, and Seconds (within 24 hours). Reset offset clears it.
  • Use this when a control's internal clock has drifted, was set incorrectly, or wasn't adjusted for daylight saving. The correction is applied retrospectively, so fixing the offset after downloads have come in re-times the affected punches.

Faulty (Normal only) ​

  • Control is faulty (non-functional) — toggle on when a control's unit failed during the event and some competitors couldn't punch it. The control is then never required: missing it is never a Missing Punch, on every course, for downloads already processed as well as those still to come.
  • It keeps its place in the course. Competitors still ran to it and past it, so it stays in the control sequence — the course length still measures through it, and it still gets its own numbered row in splits printouts, results exports and analysis. That's what keeps the control numbers a competitor reads on their splits matching the ones printed on their map. A competitor who did punch it before it failed keeps that split time; one who couldn't simply has a blank there.
  • Live radio passings for it are still ignored — a failed unit shouldn't report competitors through it on the tracking and commentary screens.
  • A faulty control can't also have a replacement code or a time offset — neither applies to a unit that has failed. While the control is faulty the Replacement and Time offset tabs are unavailable; while either of those is set, the Faulty tab is unavailable, so clear it first.
  • Use this when a unit dies mid-event and isn't replaced. If you instead swapped in a working unit with a different code, set a Replacement instead, so punches on the new code still count. If the control was only out of place for some runners, leave it as it is and mark it visited for each of them instead — see Controls and hardware.

Points (score courses only) ​

  • Points for this control — what visiting it is worth on a score course. Leave it blank to use the event's default, which is what almost every score event wants. See Points for score courses.

Points for score courses ​

At an event with a score course, every normal control has a value. The Controls page gains a Points column — type straight into it to price a control — and each control's edit dialog a Points tab. A blank value means the default: the event's Points per control, or the class's own default where the class being scored sets one. 0 is a real value, a control worth nothing.

A control's points are shared by every score course at the event, so they can also be edited from a course's Controls tab. A course file can give a control a different price on one particular course; that price belongs to the course and is changed there. See Score and scatter courses.

Checking a control's clock ​

When meshO Control radios relay a control's punches, Manager compares the time the station stamped on each punch with the time it arrived, and estimates how far the station's clock is out. The Clock column shows the result (Clock OK, or the estimate); anything over five seconds is highlighted there and raised on the dashboard. The column is blank for a control no meshO Control radio has reported.

Open the control and go to its Clock tab to see the punches the figure is drawn from, delivery statistics and a breakdown by radio unit. If the clock is out, Use suggested offset sets the time offset for you. Punches that arrived in one burst after a radio outage can't show whether the clock is right, so the tab waits for one that arrives on its own.

Marking radio controls and setting their priority ​

Why mark radio controls — and why prioritise them ​

More radios is better. There's no downside to having lots of radio controls on a course — the more points a course reports from, the more Manager has to work with:

  • Better predictions. With more splits coming in, Manager has more data to project finish times and standings, so its live predictions are sharper.
  • A better view for commentators. Each extra radio is another vantage point on the race. Commentators can see how competitors are doing through the course and how the race is unfolding, rather than guessing between sparse splits.
  • Safety. Frequent radio reports mean you can see who's out on the course and roughly where they are — useful for spotting a competitor who's overdue or has stopped reporting.

So mark every control that has a radio station on it (or let Manager do it for you — see Auto-marking controls as radios). Before the event, the Radio control placement screen, reached from the Map page, lets you choose which controls carry a radio and see whether each one can get its punches back to meshO Prime.

Priority is about the screen, not the data. Marking lots of radios doesn't crowd your displays, because the priority is a separate decision. Leaderboard screens have limited room, so in practice you only want about 3 or 4 radio controls shown per course — maybe a few more for elite courses where there's more interest. The priority is how you choose which of your many radios win that limited space, rather than leaving it to Manager. Capture everything live, then promote just the most important controls (arena passes, run-ins, the last control) to High and hide the rest.

How to do it ​

Making a control a radio control is a two-step idea:

  1. Mark the control as a radio — the Is radio flag on the control (above). This tells Manager the control reports live punches. Manager can also set this for you automatically as punches arrive — see Auto-marking controls as radios below.
  2. Choose how each class displays it — done per class on the Classes page, in the Radio controls (including priority) column.

A radio control only appears for the classes whose courses actually pass through it. On the Classes page each such control shows as a chip with a priority selector:

  • High
  • Medium
  • Low
  • Hide

A Leaderboard screen has a Max radios setting that limits how many radio controls a screen shows at once, so the priority decides which radio controls win that space for a given class. Set the spectator-facing controls (arena passes, run-ins) to High, and Hide any you don't want on screen for that class.

For relay classes the radio controls are grouped by leg (Leg 1, Leg 2, …), so you can give each leg its own set of live splits.

Note: A normal control can be shared by many courses and classes. Marking it as a radio once makes it available everywhere it's used — you then tune its priority class by class.

Auto-marking controls as radios ​

You usually don't have to tick Is radio for each control by hand. By default Manager marks a control as a radio control automatically the first time a live radio punch arrives for it — so as your radio stations come online during the event, the controls they sit on light up on their own and start appearing in live tracking, Leaderboard and Commentary.

This is controlled by an event-level setting. Open Event details (the button at the top of the dashboard — see Editing event details) and go to the Radio controls tab:

  • Auto-mark controls as radio controls — on by default. When a radio punch arrives for a course control, automatically mark that control as a radio control so it appears in live tracking, Leaderboard, Commentary, etc — no need to tick each one by hand.

Turn it off if you'd rather choose your radio controls deliberately — for example when some controls report punches that you don't want surfaced as live splits. With it off, only the controls you've marked Is radio yourself are treated as radios. Only normal course controls are auto-marked; Start, Finish and Check punches never trigger it (those are resolved by the event's code lists — see Start, Finish and Check codes below).

Start, Finish and Check codes ​

Because Start, Finish and Check radio punches just carry a code (no special meaning), Manager needs to know which codes represent these special punches. These lists live on the event itself, not on the controls.

Why these mappings matter ​

Downloads and radio punches tell Manager about Start, Finish and Check in opposite ways:

  • A card download records the special meaning — the card itself knows this punch was a Start, a Finish or a Check — but doesn't need a course code to convey it. Manager reads the meaning straight off the card.
  • A radio punch carries only the code the unit was programmed with, never the special meaning. A radio punch of code 1 is just "code 1" on the wire — Manager has no way to know that's your Start unit unless you tell it.

That's the whole reason these lists exist. Event operators program their Start, Finish and Check units with a code of their choosing — for example Start = 1, Finish = 2, Check = 3 — using SportIdent's SiConfig+ application. Any code from 1 to 13 can be used for these special stations. Whatever you chose there, you must mirror here so Manager can translate the radio punches.

Warning: If your Start unit is programmed as code 1 and it sends radio punches, you must list 1 under Start codes. Otherwise Manager sees a radio punch of code 1, finds it in none of the three lists, and treats it as a regular control along the course — runners appear to "punch" a phantom control instead of starting. Getting these mappings right is what makes live Start/Finish/Check work.

Setting the codes ​

Open Event details (the button at the top of the dashboard — see Editing event details) and go to the Radio controls tab. You'll find three fields:

  • Start codes
  • Finish codes
  • Check codes

Enter comma-separated codes in each (you can list more than one per field if you run several units with different codes). The same code can't appear in more than one field. As the dialog explains: Radio Control punches are only transmitted with the control code, not a "Start", "Finish" or "Check" punch. Configure the codes that you use for these units below so that meshO Manager can interpret the radio punches correctly. Any other codes are treated as regular radio controls along the course. New events take these lists from your defaults in Settings.

In other words: a radio punch arriving on a code listed under Finish codes is read as a finish punch; a code that's in none of the three lists is read as a normal control along the course. Card downloads carry the special meaning directly, so these lists matter only for radio punches.

These codes are only for the start, finish and check units. Don't add a numbered control's code here to make it a course's start or finish: every radio punch at it would become a start or finish on every course, and card downloads would ignore it. Set the course's Start to First control or its Finish to Last control instead. See Starting or finishing at a numbered control.

Multiple Start, Finish and Check controls ​

An event can have more than one Start or Finish — for split starts, a separate finish chute, multiple Check stations, and so on. Each course independently picks its Start and Finish in the Edit course dialog, so a map with two starts imports as courses anchored at different Start controls. The Start / Finish dropdowns there list the Start and Finish controls you've defined, plus First control and Last control for a course that starts or finishes at a numbered control instead.

When you add a Start or Finish, the Add control dialog auto-numbers it (Start, Start 2, Start 3, …); you can rename it afterwards on the Edit control dialog's Name tab. You can't delete the last Start or Finish — an event must always keep at least one of each — and you can't delete a Start or Finish that a course still uses until those courses are reassigned. The Check control is permanent: it can't be renamed or deleted, only given a time offset.

How controls relate to courses and classes ​

  • Courses anchor to a Start and a Finish (by identity, not code) and hold an ordered list of the normal control codes in between. A normal control is shown as used by a course when one of its codes appears in that course. See Classes and courses.
  • Classes inherit their radio controls from the courses assigned to them: a class shows the radio controls that lie on its course(s), and you set the display priority per class.
  • Shared controls are the norm — the same physical control (and the same code) is reused across many courses, and Manager keeps a single control for it. The Courses column shows how widely a control is used.

Renumbered or swapped controls ​

If a control's physical station is swapped mid-event for one with a different number — or the wrong unit was put out — you don't have to edit every course. Instead, open the control's Replacement tab and set a Replacement Code. Manager then accepts punches on the new code as if they were on the original, so existing courses and results stay valid. The Controls page shows the original code struck through with the replacement beside it.

Deleting all controls ​

Actions → Delete all controls… clears the controls list in one step — useful when a course import created a set of controls you'd rather rebuild than correct.

Manager confirms first and lists what else changes:

  • Only the normal controls go, along with their radio setting, radio name, replacement code and time offset.
  • Start, Finish and Check are kept. Courses anchor to them by identity, and an event always needs at least one of each, so a delete-all never removes them. The confirmation reports how many were kept.
  • Courses keep their control codes. The controls themselves come back automatically the next time a course is saved or imported, so this is a way to reset the radio and timing settings without touching the courses.
  • Measured leg distances are kept, and apply again if the same controls come back.

This cannot be undone. On a live event, back the event up first — and remember that clearing the radio settings stops radio punches from being matched until the controls are marked as radios again.

Leg distances ​

Distances between consecutive controls are kept in one shared bank for the whole event, keyed by the identity of the two controls. Edit them on the Legs page, under Course in the event menu. Editing the distance for a leg once updates every course that traverses it, and a leg can also carry an untimed allowance for a road crossing. See Leg distances for the full explanation.
