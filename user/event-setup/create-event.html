Creating an event ​

Audience: Event organisers setting up a new competition in Manager.

How to create an event, edit its settings, and understand the options that shape how the event runs.

The Events page ​

Open Manager and navigate to Events (this is where you land by default). The page has two tabs:

  • Upcoming — future and currently-running events, newest first.
  • History — past and completed events, with a search field to filter by name.

Each event is shown as a card with its name, date, and a coloured status chip — one of Setup mode, Event in progress, Event completed, or Event abandoned.

Clicking a card opens that event's dashboard. If you try to open a different event while another one is currently in progress, Manager asks you to confirm — the live event keeps running in the background.

A multi-stage event appears as a single row with its stages nested underneath; clicking the header opens the carnival's overview, and clicking a stage opens that stage's event like any other.

Each event card carries its actions below the status chip: a download icon that exports a zip backup of the event, a duplicate icon that builds a new event from this one, and a delete icon (red trash) that permanently removes it. A cloud icon appears as well when cloud sync is configured, and publishes the event to the cloud there and then.

A finished event also shows a small grey cloud beside its status chip: with a tick once it has been published to the cloud, or with a clock while it is waiting for this computer to be online. Finishing an event publishes it automatically unless that is turned off — see Cloud sync in Settings.

The Cloud sync tab of Event details is where one event decides for itself whether finishing it publishes it (or follows the setting in Settings), shows where it stands on the cloud with a link to its public page, and lists every sync it has had — an event finished, restarted for a late card and finished again is synced more than once, and each is listed. Delete from the cloud takes the event off the public site; the event on this computer is left as it is, and its automatic sync is switched off so it is not published again the next time it is finished.

Creating a new event ​

Click New event (top of the page, or in the welcome section if this is your first event).

If you have Eventor configured, the button opens a menu with two ways to create an event:

  • Create manually — an empty event with default settings, which you then edit to fit your competition. Described below.
  • Import from Eventor — classes, competitors, clubs and start times pulled from an event published on Eventor. See Creating an event from Eventor.

Without Eventor configured there is nothing to choose between, so the button goes straight to the manual dialog.

Creating an event manually ​

The New event dialog asks for a name and a date — both pre-filled, so you can leave them — and what you're creating:

  • Individual — an ordinary event.
  • Relay — a team event; reveals a Number of legs field (default 3) and a Mass start time.
  • Multi-stage — a competition run across several events; asks only which kind: a Carnival (stages scored and added up) or a Knock-out (rounds whose field comes from the round before).

Click Create and Manager creates it and opens it — an event at its dashboard, a multi-stage competition at its overview. A carnival arrives with three placeholder stages on consecutive days from the date you chose, which you then re-date on its Stages tab; a knock-out arrives empty, because its rounds are generated from a template.

Note: The event type is fixed at creation and can't be changed later, and so is a multi-stage competition's kind. Most events are Individual; for team relays choose Relay — see Relay events. A Multi-stage event isn't a third event type: it's a container whose stages are ordinary events, so nothing about running a stage changes — see Multi-stage events and Knock-out competitions.

The new event is in Setup mode and gets:

  • Name — what you typed, pre-filled with today's day of the week (e.g. "Thursday event").
  • Date — what you chose, pre-filled with today.
  • Everything else — inherited from Settings → Event Defaults (start/finish unit numbers, event type, radio settings, etc.).

Open the event details from the dashboard (see Editing event details below) and edit anything else you need to before adding competitors or going live.

Tip: The defaults are there to save you repeating the same choices event after event. If you find yourself changing the same field on every new event, set it in Settings → Event Defaults instead.

Editing event details ​

Once inside an event, click the edit icon on the Event header card (on the dashboard) to open the Event Details dialog. This is where you configure everything about how the event runs.

If the event was imported from Eventor, the dialog title shows an Eventor ID chip for traceability.

The dialog is organised into tabs down the left-hand side:

  • Details — name, date, description, classification
  • Score — at a score event only: its Time limit (minutes) and Points per control
  • Starts — mass start, punching-start override (a relay event has Relay here instead; see Relay events)
  • Radio controls — meshO Prime, SI codes for start/finish/check, radio-punch forwarding, SIRAP
  • Live results — publishing this event to liveresultat.orientering.se
  • Cloud sync — publishing this event to a cloud meshO Manager, so spectators can browse it online
  • Quarantine — holding back elite classes' results until a release; see Results quarantine
  • Printing — when splits print and what is on them, result labels, cards read over the radio network, and the QR code
  • Hire items — whether a download warns the desk to collect a hire item; see Hire items
  • Low-key event — enter unknown cards and make courses from them, and ignore the competitor registry or the hire-card list; see Low-key events
  • Extensions — enable and configure installed extensions
  • Backup & export — periodic backups of the event, and a live export of its results on a schedule

Details ​

  • Event name — editable at any time. Must be at least 3 characters.
  • Event date — editable in Setup mode; locked once the event goes Live.
  • Description — optional free-text notes about the event.
  • Event Type — Individual, Relay, etc. Affects how competitors and start times are organised.
  • Competition Level — Local, National, etc. Currently informational; used by exports and reports.
  • Discipline — the course length (Sprint, Middle, Long, Ultra Long) or the competition format (Knock Out Sprint, Sprint Relay, Mass Start, Pursuit, Relay, Mixed Relay, Qualification, PreO, TempO). Currently informational; used by exports and reports. Picking a relay discipline describes the race — it doesn't make the event a relay, which is what Event Type does.
  • Course Format — what you flag the event as, and what a new course starts as. Each course can be changed on its own.
  • Use sub-second timing — off unless you turn it on, and off is right for almost every event. Left off, a whole second is the smallest difference Manager will separate two runners by: two people who finish inside the same second dead-heat, two splits inside the same second share the leg rank, and a gap that small is shown as no gap at all. Turn it on for a race actually timed to fractions — a sprint final, a knock-out heat — and Manager decides splits, places and gaps on the fractions the cards carry, and shows race times to a hundredth (30:00.23). Only race times show the fraction: split times, cumulative times and gaps stay in whole seconds wherever they appear, so a splits table doesn't become a wall of digits. You can change it whenever you like, including after the results are in — nothing is thrown away either way.
  • Course Closure — optional. The time of day every competitor has to be back. Off unless you turn it on; when you do, the time defaults to 15:00:00. Once that time of day passes, Manager settles whoever nobody has accounted for — anyone still out is marked Overtime, anyone who never started DNS (unless they checked in and nothing has seen them since — they become Overtime, so they stay on your On Course list), and a radio finish with no card downloaded yet DNF — and a card downloaded afterwards whose finish punch was late is scored Overtime rather than OK. It never overrides a status you set yourself, and anyone marked Overtime with nothing to show they came back stays on the On Course list. See Safety check.

Radio Controls ​

This tab covers everything about radio-delivered punches.

meshO Prime — toggle on if you have a meshO Prime radio network in the field. When on, Manager listens for radio punches from your Prime base unit.

SI codes — radio punches carry only an SI control code (e.g. 2), not a "start" / "finish" / "check". Manager uses these fields to know what each code means at this event. Any code not listed here is treated as a regular radio control along a course.

  • Start Codes — SI codes of your start units.
  • Finish Codes — SI codes of your finish units.
  • Check Codes — SI codes of your check units.

Enter one or more codes per field, comma-separated. The same code can't appear in more than one field. These remain editable during the event.

Forward Radio Punches (visible only when meshO Prime is on) — forwards each incoming radio punch to the destinations configured in Settings → Radio Punch Forwarding.

Accept SIRAP Punches — accept incoming SIRAP-protocol punches from external sources.

Starts ​

Mass Start — toggle on if all or most competitor starts at the same time. When on, set the Mass Start Time. Defaults to 10:00:00 the first time you enable it.

Allow punching starts to override allocated starts — if a competitor punches a start unit, use that punch as their start time even if they had an allocated start time. Turn off if your event uses strict allocated starts only. This can also be overriden for each competitor, if required.

Backup & export ​

This tab holds the things that write files on a schedule: the event's auto backup, its copy on an external drive, and a live export of its results.

Auto backup ​

Enable auto backup — when on, Manager periodically writes a zip backup of the event to an auto-backup/ directory inside the event's folder while the event is running. You can restore from these zips with the standard restore-from-backup flow. Off unless you turn it on, for this event or for every new event in Settings → Auto backup.

Backup frequency — how often to take a backup (e.g. every 15 minutes).

Backups to keep — how many of this event's auto-backups are kept: 1, 2, 5, 10, or All. Once a new backup has been written, any older ones beyond that number are deleted, so the folder doesn't grow all day. Files you put in the folder yourself are left alone.

Backup to external drive — the auto-backup above is on the same disk as the event, so if that disk fails it goes too. Turn this on to copy a backup of the event to a USB drive or external disk as well, while the event is running. Then choose the Drive from the list of drives attached to the computer running meshO Manager (plug it in and press Refresh if it is not there yet); the disk holding the event data is never offered. The drive is recognised by its own ID, or its name if it has none, not by where it is plugged in, so moving it to another port is fine, and a different drive plugged in where it was is never written to. A line under the list says whether the chosen drive will take a backup now. The copy has its own Backup frequency (10, 15, 30, 60 or 120 minutes — a USB drive is much slower than the computer's own disk, so you will usually want it less often than the local backup) and its own Backups to keep. Copies go in a meshO-backups folder on the drive, one folder per event. If the drive is not plugged in, full or write-protected when a copy is due, an alert says so, and a second alert says when copies are being taken again.

Live export ​

Export live results on a schedule — when on, Manager writes the event's results as an IOF XML file every so often (Export every), so a results system watching a folder can pick them up. Include radio controls adds runners still on course and their radio-control passing times; off, only downloaded results are exported. File naming: Overwrite a single file always writes results.xml, which systems that watch the folder (such as LiveResults EmmaClient) need; New file for each export keeps every export.

Printing ​

Per-event overrides for the settings in Settings → Printing: when this event's splits print and what is on them, its result labels, and where cards read over the radio network print. The printers themselves, and where each computer's prints go, are not the event's — they are set up in Settings → Printing and stay set up from one event to the next. See Printing splits.

  • Automatic print splits on download, Hold a mis-punch printout, Print meshO logo, Print top 3 places, Print mistakes, Print strong legs — each Use global setting (on/off), On for this event or Off for this event.
  • Splits language — the installation's, or a language of this event's own.
  • Result label overrides — Result labels on or off for this event, and the Label printer; the layout stays the one in Settings.
  • Cards read over the radio network — where a card read by a radio download station prints its Splits and Labels, and Print splits only when the status is OK, each overriding Settings → Printing → Radio downloads for this event.

QR code — a QR code printed at the bottom of each competitor's splits, generated from a URL template. Three modes:

  • Use global setting — uses the template from Settings → Printing → Splits print.
  • Customise for this event — set a URL template just for this event. Supported placeholders: {competitorId}, {eventId}, {cardNumber}. A Use this server's spectator URL button fills in a sensible default. You can also set a custom caption printed below the code.
  • Disable for this event — no QR code is printed, regardless of the global setting.

Extensions ​

Each installed extension appears with a switch. Enabling an extension reveals its per-event configuration fields (extensions can also have app-wide configuration set on the Extensions page).

If no extensions are installed, the tab shows a hint pointing to the Extensions page.

Moving an event to another computer ​

To hand a set-up event to whoever is running it on the day, or move it to the laptop that goes to the event, back it up and restore it there. See Moving an event to another computer for the steps and the checks to make afterwards.

Duplicating an event ​

Most events are the next running of one you have already set up. Rather than building it again, click the duplicate icon on the event's card.

The dialog asks for the name and date of the new event, and whether to bring the field with it. The name starts as the name of the event you are duplicating — change it if this running has its own name, or leave it as it is for the next race in a series. The setup always comes across: classes, courses, controls, clubs, radio-control assignments, spectator screens, the map and its calibration, and every event setting.

One switch decides the rest, and it starts off:

  • Keep all competitors — off, so the new event starts with nobody entered. Turn it on when the same field is running again and you would rather edit the entries than re-import them. You get the people, not their race: everyone carried across keeps their name, club, class, card number and drawn start time, and arrives as an entry that has not run.

A duplicate never carries last week's race. Whichever way you answer that switch, the copy has no card downloads, no radio punches, no punch corrections, no results, and none of the Start, Check and Finish times recovered from station backup memory. Anything you had ruled at the last event, such as a disqualification, is left behind too, and so is a start time that came from punching the start or check unit rather than from the start list. So is an On start punch of Allow punching start that Manager switched on because the competitor punched the start before their drawn time; one you chose yourself comes across. This is not a choice because there is no good answer to it: the times belong to another day, a card kept without its owner waits to attach itself to whoever is entered on that card next time, and a copy holding either would say a competitor who has not started is already out on course. If you want last week's race, you still have last week's event.

If the new event is on different terrain, replace the map on the new event once it is created.

The date can be today or later. Manager creates the copy and opens it, ready for this event's entries.

The copy is a new event in every sense: its own event id, and none of the identity of the one it came from. It has not been started, it is not published to liveresultat or to the cloud, it is not a stage of a multi-stage event, and it carries neither the original's Eventor link nor its audit trail. The event you duplicated is not touched.

Deleting an event ​

On the Events page, click the red trash icon on the event's card. Confirm the prompt. This permanently removes the event and all its data. There is no undo.

What's locked when the event is in progress ​

Once you click Start event, the event date becomes read-only. Changing the date of a running event would invalidate time calculations.

Everything else — name, description, classification, radio settings, unit codes, starts configuration, competitors, classes, courses, start times — remains editable throughout the event.
